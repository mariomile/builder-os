# Gate 4 — Shape

Read when running gate 4. E.1, E.2 and the procedure in `SKILL.md` apply too. **Acceptance:** whoever owns the product decision, with a technical reviewer for high-risk changes, recorded with `record 4 --accepted-by "who"` (`SKILL.md`, Acceptance).

| # | Condition | Check |
|---|-----------|-------|
| 4.1 | Acceptance criteria are testable assertions | Each starts with a subject and a verifiable verb; no "should be intuitive" |
| 4.2 | Out-of-scope list is non-empty | An empty out-of-scope list means the scope was never bounded |
| 4.3 | Every flow has error and empty states | Per flow, both states enumerated |
| 4.4 | Tracking plan measures the Phase 2 metric | Named events map to the success metric. Skipped on the change track, which has no phase 2 metric |
| 4.5 | Accessibility floor stated | Keyboard path, contrast target, focus order |
| 4.6 | Model output has an eval dataset | Existing JSON/JSONL cases (`id`, `input`, `expected`, optional `judge`, boolean `must_pass`) or Markdown case table (# / Input / Expected / Judge / Must pass). Full ≥20, lite ≥10 valid unique cases, threshold 0–100, named judge, at least one must-pass case. Prose counts and unsupported formats fail |
| 4.7 | Constraint conflicts stated, each with who decides | A `## Conflicts` section exists, stating either the conflicts between `PRODUCT.md` and `TECH.md` constraints or that none were found. Every conflict row names who decides |
| 4.8 | The stack was decided with a person | `## Stack` lists every layer the work touches as inherited, decided or not needed; every decided row names who decided it; every linked ADR exists in `decisions/`; `## What we chose` summarizes the choices for the person accepting |
| 4.9 | The look was chosen from rendered versions | `DESIGN.md` → `## Visual direction` shows at least 3 versions on a new product in full mode, 2 on the feature track or in lite mode, each version file exists; `**Chosen:**`, `**Chosen by:**` (a person), `**Design kit:**` and the tokens are filled. Wherever two or more versions are needed, `**References:**` lists real screens studied before rendering (files that exist, or `doc` tags): 3 on a new product in full mode, 2 otherwise; and the versions table has an `Avoids` column naming, per version, the generic default it steers away from. Or `**Visual direction:** not applicable, {reason}` when there is no interface. On the change track one version is enough, or `**Visual direction:** inherited, {reason}` when no screen changes its composition |
| 4.10 | The domain was modeled with a person | `DESIGN.md` → `## Domain model`: an Entities table; a `### Transitions: {entity}` table naming who for every entity with a lifecycle; `### Invariants`; a `### Data` table; `**Rules decided by:**` a person; a referenced prototype file exists. Or `**Domain model:** not applicable, {reason}` when nothing changes state or shape |
| 4.11 | The impact on what exists is handled | `04-spec.md` → `## Impact on what exists` has a row for existing data, contracts (APIs, webhooks, exports, integrations), tracking events, permissions and current users, each with its handling ("nothing to do" with the reason counts). Or `**Impact on what exists:** not applicable, {reason}` when nothing exists yet |
| 4.12 | What a machine cannot check is written down | `04-spec.md` → `## Quality bar` table (Area / Criteria / Not applicable because) with a row for permissions, personal data and performance. Each row cites acceptance criteria that exist, or gives the reason it does not apply. Accessibility, end-to-end, dependencies and secrets are not here: they are automatic checks (5.10) |
| 4.13 | Someone from the ICP saw it before the build (product track) | `04-spec.md` → `## Real users` cites at least one `interview`, `doc` or `data` tag: one session where a person from the ICP walked the problem, the concept or the clickable prototype. A plan to talk to users fails. Skipped on the spike, change and feature tracks |
| 4.14 | Money before the build (product track, for sale) | `**Willingness to pay:**` in the spec cites an `interview`, `doc` or `data` tag: what a person from the ICP did when shown the price (a pre-order, a letter of intent, a click on a price, a price accepted in the real-user session). An opinion about the price fails. `## Stack` has a payments row, inherited or decided: how the product takes money and who handles tax and invoices. Skipped when `PRODUCT.md` says not for sale and on the other tracks |
| 4.15 | No scale work before PMF | Model-judged at `idea` and `pre-PMF`: nothing in the spec is optimization, enterprise control or infrastructure for load nobody has. Skipped after PMF |
| 4.16 | The agent's behavior is designed (model output) | `04-spec.md` → `## Agent behavior` (`agent-design`): an autonomy table (Action / Autonomy / Why / Criterion) where every action is `does`, `proposes`, `asks` or `never`, and every `asks` row cites an acceptance criterion that exists; `**Hand-off:**`; `**Degradation:**`; `**Latency budget:**` with a number; `### Injection surfaces` (Surface / What could arrive / Mitigation / Eval case), each row with a mitigation and an eval case that is must-pass in the 4.6 dataset. Skipped without model output |
| 4.17 | The first day is designed (product track) | `DESIGN.md` → `## Flows` has `### First day`, from the first visit to the first useful outcome; the spec's `**Activation:**` cites an acceptance criterion that exists and names an event from the tracking plan. Skipped on the other tracks |
